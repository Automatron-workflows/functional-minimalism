# Audit and changes for Functional Minimalism v0.2

## Product findings

1. The v0.1 opening view resembled a component showcase. The harness's value and the reason to install it were not sufficiently visible.
2. “Design Harness” described a category without giving this project an identity.
3. Setup installed files but left the user to adapt a JSON contract manually before they had a first useful brief. The example project ID could also mismatch the user's memory scope.
4. The illustrated Before version was a hand-authored example, but its relationship to actual model performance needed to remain explicit.
5. Source checks passed; browser verification remained blocked. A new visual treatment must not inherit a claim of visual verification from those checks.
6. Malformed existing instruction markers were detected after reference files could already have been written. This validation now runs in preflight.

7. Functional minimalism needed a practical definition: reduce interpretation and repetition while retaining useful information. The workflow now carries a Rams reference and software review practices, without implying endorsement or a universal visual style.

## Changes

Functional Minimalism adds a name, brand assets, concise why/what/how, a visual workflow film, and a separate interactive workshop. The film demonstrates the harness rather than presenting one app as the product. A setup command now writes a correctly scoped first-screen contract and generated brief. Doctor checks the pack, mappings, instructions, and selected screen without pretending to observe the agent's context. The original command and data schemas remain compatible.

The live Figma adapter, Alps pack, and cross-model/participant studies remain out of scope for this release. Naming and product presentation do not close those evidence gaps.
