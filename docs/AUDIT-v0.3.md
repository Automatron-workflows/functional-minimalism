# Audit and continuation · v0.3

The product's benefit needed to move from remembering taste to reducing repeated design work. The brand now uses the requested name Functional Minimalism, with the promise Better UI. Fewer retries.

## Changes

- Replaced the previous name across the UI, CLI, package, documentation and downloads.
- Made the purpose explicit: start closer to a useful minimal interface, so less time and token usage goes into corrective prompting.
- Added compact briefs without dropping the task, component rules or accepted scope. New-project setup uses compact context by default.
- Added a reproducible context-size report and a paired experiment protocol. No unmeasured token or time percentages are advertised.
- Added GitHub Pages publication and browser-check steps alongside existing tests and source checks.
- Retained Rams's principles as attributed inspiration and our practical review criteria. Functional minimalism preserves essential information.

## Acceptance

Run automated tests, build/source checks, packaged setup, browser interactions and narrow-layout review. Inspect the actual deployed URL. Keep automated checks, visual observations and user research distinct.
