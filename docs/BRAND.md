# Functional Minimalism

**Better UI. Fewer retries.**

An Automatron design harness that starts AI interface work with useful, minimal design defaults and the project's actual design system.

## Why

Correcting the same generic interface repeatedly costs time and tokens. Put good constraints into the first brief, retain explicit corrections, and reuse them on the next screen. The intended benefit is better first drafts with less rework. End-to-end savings have not yet been measured.

## What

Project instructions, versioned design packs, task-specific briefs, scoped design memory, and source/rendered-evidence checks. It is a harness for the coding agent, not a model, a hosted generation service, or one aesthetic imposed on all products.

## How

Set up the project. Define one person's task. Generate the compact brief with the relevant components and accepted decisions. Build with the agent. Render, exercise, and repair. Retain only the corrections the user accepts.

## Name and family

Use **Functional Minimalism** in prose and **functional minimalism** in the wordmark. Use `functional-minimalism` for the repository, source folder, CLI and scoped package. The name states the philosophy directly. It is descriptive; no exclusive trademark or domain claim is made.

## Design philosophy

[Our software review practices](../references/functional-minimalism.md) draw on Dieter Rams's principles. Function determines what stays. Familiar labels, essential data, errors, permissions and recovery are part of minimalism. The reference is not an endorsement, certification or instruction to reproduce Braun's products.

## Visual identity

- A plain lowercase wordmark on the page; the bracket/minus mark is used for the browser icon.
- Midnight canvas, warm ivory, restrained copper accents. These belong to the demonstration, not every consuming application.
- System sans-serif for the product and page. Authored source drafts may use their own model-like typography while they remain subordinate. Copper is reserved for the functional action inside the composed screen. No remote fonts.
- The landing comparison is manual: model result thumbnails sit under each other in a stable rail, selecting one updates a before/after pair, and dragging the image or using the switch reveals that model's adapted review while keeping its composition, palette and typography. Each result has one accent action. The landing shell's copper belongs to the page, not the adapted results. Visible model names identify the authored sources; the information control states they are not actual outputs.
- Short visual comparisons, one manual before/after control, and optional details. The comparison does not autoplay; the viewer sets the split.

## Claims

Say: built to reduce repeated design corrections, designed for better first drafts, preserves accepted decisions, compact context.

Measure before claiming: saved minutes, fewer model tokens, reduced cost, better usability, first-pass success rates. Context bytes are not model tokens, and a shorter brief does not establish an end-to-end saving. The harness itself adds context.

The landing comparison names common model defaults to make the comparison legible. The drafts are authored illustrations, not actual model outputs. No cross-model study was run. The workshop uses fictional data and real local checks. A live Figma importer and Alps source pack remain pending.
