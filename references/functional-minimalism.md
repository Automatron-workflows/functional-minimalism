# Functional minimalism

Formthread's philosophy: reduce the effort needed to understand and use an interface. Keep what helps the person act; remove what competes with it. A dense table can be right. A sparse screen can still be confusing.

The reference is Dieter Rams's ten principles, documented by [Vitsœ](https://www.vitsoe.com/gb/about/good-design). His phrase “Less, but better” captures the ambition. Functional minimalism is our name for this application, not a term or endorsement attributed to Rams.

The following are Formthread's own software review practices, inspired by that reference:

| Lens | Review practice |
| --- | --- |
| Purpose | Start with a person's task, not a showcase of AI capabilities. |
| Utility | Complete the useful action before adding features. |
| Craft | Use proportion, typography and spacing deliberately. |
| Comprehension | Preserve meaningful labels, units and state. |
| Restraint | Remove decoration that competes with the task. |
| Truth | Disclose simulations; avoid invented performance claims. |
| Continuity | Reuse the established system and accepted decisions. |
| Detail | Exercise errors, focus, narrow screens and recovery. |
| Resources | Prefer small assets, no unnecessary dependencies, and paused hidden motion. This is not an environmental-impact measurement. |
| Essentials | Remove duplicate explanation before consequential information. |

This is human review guidance, not a Rams score or automatic design certification. Judge each application against its task and brand; do not impose one universal minimalist aesthetic.
